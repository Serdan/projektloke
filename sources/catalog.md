# Source catalog policy

The public site keeps machine-readable source metadata in `site/content/data/sources.json`.

This directory is for preservation and acquisition rather than a second competing metadata database.

## `inbox/`

New material awaiting review, naming and classification.

## `archive/`

Preserved copies of fragile or important primary material: PDFs, screenshots, exported pages, transcripts and similar artifacts. Archive files should use stable descriptive names and, where practical, correspond to a source ID used by the site.

## Rules

- Do not duplicate source metadata manually when the site source registry already contains it.
- Record provenance for locally preserved material.
- Preserve originals; transformations belong beside them and should be clearly named.
- Do not commit large archives or material with privacy/copyright concerns merely because it is useful internally.
